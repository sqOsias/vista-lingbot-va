# 架构与代码对应

```text
过去真实图像/事件 ──> 外部证据库/视觉规划器 ──> 目标条件（文字、目标框或三维位置）
                                                   │
当前三相机图像 + 当前机器人状态 ───────────────────┼──> 冻结 LingBot-VA
                                                   │        │
                                                   │        └─> 原生相对动作张量 (16,2,16)
                                                   │                    │
RMBench 真实已执行历史 <── 历史编码/commit <── MPLib执行 <── 数值解码为双臂EE命令
        │
        └──> 独立评分与审计（不回流为策略输入）
```

| 模块 | 责任 | 主要输入 | 主要输出 |
|---|---|---|---|
| `model/server.py` | 加载并冻结 posttrain-robotwin | 三相机 RGB、状态、文字、已执行历史 | LingBot 原生动作张量、缓存收据 |
| `memory/` | 保存可追溯历史并形成目标条件 | 过去/当前真实图像、实际执行事件 | 证据引用、目标框、短目标文字 |
| `perception/rgbd.py` | 将视觉框转成度量位置 | RGB、深度/Position、相机标定、目标框 | 三维中心、桌面高度、方向与不确定性 |
| `control/robotwin_contract.py` | 复现发布数据的旋转和相对动作合同 | 模型16维相对动作、episode原点 | RMBench 双臂末端命令及历史张量 |
| `control/spatial_executor.py` | 外部技能执行，主要用于前缀或解析基线 | 三维目标与技能序列 | 实际EE命令和测量轨迹 |
| `sim/environment.py` | 创建固定相机/种子的 RMBench 环境 | 任务、seed、D435配置 | 原始任务实例和三相机观察 |
| `evaluation/smoke.py` | 迁移验收 | 模型服务、固定场景 | 一块WAM动作的完整执行证据 |

研究中的核心连接仍是“外部历史产生的目标条件，能否让同一个冻结 WAM 在相同执行器和预算下获得物理收益”。接口可运行、动作被执行、任务成功和记忆增益必须分别报告。
